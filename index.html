System Design Framework

When designing the system, especially in the interviews, you need to make sure that you are not lost into the one concept and keep rambling around that concept for long. To prevent from hallucinations or stay away from the situation where one gets too deep into one concept and apparently waste all their time on one thing, there is a framework that almost all candidates follow to design the system completely and successfully.

Requirements

Functional Requirements

These requirements should focus on the High Level Design and should be enough to create a functional software despite considering the optimisation, scalability and similar kind of factors.

Non-Functional Requirements

These requirements should focus on Deep Dives that includes an optimisation of the High Level (Functional) System.

We need to think about the category of the system →

  • Scalable reads
  • Scalable writes
  • Maybe Both of them

Which individual properties should we focus on from CAP theorem →

  • C → Consistency
  • A → Availability
  • P → Partition Tolerance

There is one key concept that I have found very common in system design questions. Most of the time, we tend to create a distributed architecture, and for distributed environments we can't risk the Partition Tolerance property. Because if it occurs then the nodes won't be able to communicate with each other and so forth.

Entities

We need to identify the core entities required which helps us to build a basic Data Model and build the structure of API's request, response bodies.

API as an interface

In most cases, we choose REST API to know how the user's interact with our system

High Level Design

Here, you'll connect the dots of all the preceding building block that we've just studied. Now the High Level System should be functional enough to meet functional requirements. It does not need to think about optimisations and stuff

Deep Dives

After creating the High Level Design, you focus on the non-functional requirements which helps you scale the system and you align your system with non-functional requirements

You will have an idea of each of the building blocks in detail by having a look at one of the examples
